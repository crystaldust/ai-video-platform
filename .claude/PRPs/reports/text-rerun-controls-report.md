# Implementation Report: 页面上重跑文本——单阶段重跑、只补出图提示词、一次打回多集（backlog #32、#33、#36）

## Summary

- **#33 只补出图提示词**：`RunNodeOptions.refsOnly` 让角色配方拿现有角色卡只跑 character-refs、只补回 `characterRefs`，模型只被问 intake。
  - `fillCharacterRefs` 补完后，把原因全部是「角色卡换了版本」的新需复核格子确认掉，备注「只补出图提示词，外形没变」。
  - 估算排除只补提示词的运行。
  - 入口：`POST /api/p/:id/refs`、命令行 `refs <dir>`、角色卡上的「补提示词」、生成失败提示的直达。
- **#36 一次打回多集**：`checkRejectMany` / `rejectMany` 在一个后台任务里依次跑，每集一条打回记录、一次运行。
  - 一集失败记下原因、接着跑下一集；连着两集出同样的错，剩下的不再试。
  - `/reject` 接受 `episodes`。打回框可以多选集，提交前先确认。结束时弹一句汇总。
- **#32 阶段卡重跑**：每张文本阶段卡底部有「重跑 · 约 ¥x」，确认框写明从头重写、下游需复核、估算。请求带 `fresh`，不沿用上一次失败留下的集。

## Deviations from Plan

1. **#33 编排的测试改了场景**：渡口样例只有第 1 集有分镜，「原有需复核」和「补完后冒出来的」落在同一格。拆成两条测试：干净项目补完后仍是 0 项；原有的需复核保留。
2. **`remedyFor` 返回值加了 `path`**：直达操作从 `/go` 换成 `/refs`，`remedy-action` 按 path 发请求。
3. **`rejectSummary` 先实现、后补测试**：没按先红后绿的顺序。
4. **连着两集出同样的错就停**（审查 LOW 采纳）：结果新增状态 `skipped`。
5. **自动确认只确认原因全部指向角色卡的格子**（审查 MEDIUM 采纳）：补提示词的同时别处改了上游，那些格子要留给人看。
