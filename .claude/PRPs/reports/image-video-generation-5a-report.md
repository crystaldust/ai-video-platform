# Implementation Report: 图片/视频生成与可靠任务（Phase 5a：后端与命令行）

## Summary

已确认的付费确认单现在能按勾选的节点和集真正去生成：

- 角色参考图：百炼 Qwen-Image 3.0；
- 关键帧：百炼 Qwen-Image 3.0；
- 视频：MiniMax H3-Lite。

付费生成做成了持久化的任务状态机。迁移 v7 重建了任务表，提交纪律是：

- 先写库，再发请求；
- 同一家供应商同一时刻只有一个提交在路上；
- 提交不自动重试，只有限流例外；
- 出现「结果未知」后，这一次运行不再往这家供应商提交。

崩溃后，在供应商的任务列表里按时间窗对账，绝不重新提交。重新查询（不花钱）和重新生成（新建任务）是两个分开的操作。预算一律按人民币比较。产出的文件进素材库，作为候选挂在角色、切、段上。命令行新增 `generate`、`tasks`、`tasks resume`、`tasks requery`、`tasks regenerate`。界面放在 5b。

## Deviations from Plan

1. **迁移 v7 的重建方式**
   - 计划：「建新表 → 复制 → 删旧表 → 改名」。
   - 实际：旧数据先抄到临时表 → 删旧表 → 用原名建新表 → 抄回来，并用 `PRAGMA defer_foreign_keys`。
   - 原因：删旧表时，SQLite 把 `task_event`、`candidate` 的孤行记成待解决的外键违例，改名不会抵消，提交时会报外键错。按原样插回父行才能抵消。迁移测试验证 `foreign_key_check` 为空。
2. **执行器的「只查询」模式**
   - 新增 `submit: false`，`tasks resume` 用它：只查询、下载，不提交。
   - 原因：计划要求恢复时不动 `planned`，执行器需要这个开关。
3. **重新查询与重新生成单独放在 `src/generate/manage.ts`**，执行器另外暴露了 `refreshTask`。计划里没细写这两个操作放在哪。
4. **审查后加固**（code-reviewer 和 security-reviewer 都没有找到重复提交的路径，以下是他们指出的「多花钱或对不上账」的漏洞）：
   - **看不懂的状态**：供应商返回看不懂的状态，按查询出错处理，不改任务状态。供应商明说查不到时转 `unknown`，不判失败。原来判失败，任务就能被重新生成，而它可能还在计费（审查报的 HIGH）。
   - **结果未知后停提交**：出现结果未知后，这一次运行不再往这家供应商提交；另一个活着的进程有「提交中」的任务时，`generate` 拒绝启动。
   - **预算**：实际费用为空时按预估算，`unknown` 也算在内；设了上限时，查不到单价的任务不提交。
   - **查询放弃**：查询成功就清零失败计数；放弃查询的任务和出错原因列进汇总（`pollGaveUp`、`problems`），并计入退出码 2。
   - **重新生成**：同一个「节点 + 标签」已经有没结束的任务时，拒绝重新生成。
   - **对账**：任务列表翻页到上限还没取完时报错，恢复时让任务保持「提交中」，不判「没到达」。
   - **地址**：`endpoints.json` 只认两家的官方域名。
   - **下载**：只走 https（跳转后也要是 https）、有超时、先看 content-length、边读边计数，临时文件在 finally 里清理。
   - **参考图**：读文件前检查路径在素材目录内。
   - **HTTP 408** 按结果未知处理；查询时遇到状态对不上，只记录，不让整个运行崩掉。

## Issues Encountered

- **迁移外键报错**：见偏差 1。
- **提示词测试的样例词**：审核拒绝测试原本选的关键词「码头」，在第 1 集的 `frame` 里一次都没出现，改成只出现在第 3、10 段的「灯」。
- **测试的预期写错了**：「查询一直出错」那条测试原本预期 34 个任务都提交。实际上放弃查询的任务仍占着并发数，所以只提交 4 个。这是更稳妥的行为，改的是测试预期，不是代码。

## Known Gaps（留到后面）

- **参考图大小没有提前校验**：百炼单张 10 MB、MiniMax 整个请求体 64 MB，超限时由供应商拒绝，任务转失败。
- **两条报错路径没有专门的测试**：「勾选的集在当前分镜里已被删除」和「角色卡缺外形描述」，代码里处理了。
- **`unknown` 任务没有命令行的「判失败」出口**：人在供应商控制台核对后，只能用 `requery --provider-id` 指定任务 id。如果核对后确认任务根本不存在，目前没有办法把它判成失败再重新生成。
- **百炼的任务列表是整个账号的**：时间窗里只有一个别的程序建的任务时，会被误认成我们的（唯一匹配）。不影响花费，但下载的图可能不对。已经写进文档。
