# 付费生成：角色参考图、关键帧、视频

确认付费确认单后，`cli generate` 按勾选的节点与集生成：

- 角色参考图：百炼 Qwen-Image 3.0；
- 关键帧：百炼 Qwen-Image 3.0；
- 视频：MiniMax H3-Lite。

产出的文件进素材库，作为候选挂在角色、切、段上。审阅与选用在 Phase 6。

```bash
cli cred set dashscope        # 从 stdin 读 key，不回显
cli cred set minimax
cli generate <dir> [--gate <id>]            # 默认用最近一张已确认的确认单
cli tasks <dir> [--status failed]           # 任务列表
cli tasks resume <dir>                      # 崩溃后恢复
cli tasks requery <dir> <任务 id> [--provider-id <id>]
cli tasks regenerate <dir> <任务 id>
```

地域与地址见 [models-and-pricing.md](models-and-pricing.md#图片视频供应商的地域)。

## 计划什么

计划的口径与估算一致（`src/estimate/usage.ts`）。用哪个模型、什么参数，都取确认单里那份估算的选择，那是人确认时看到的。

| 节点 | 任务 | 依赖 | 提示词 |
|---|---|---|---|
| `image:character-refs` | 大纲里不是功能角色的人物 × 5 视图：正面全身（锚点）、正脸大头照、侧面、背面、45° 大头照 | 锚点不挂参考；其余视图只参考锚点 | 角色卡的外形描述（`cast.json` 的 `image.prompt`）加视图取景，视图照 character-refs |
| `image:keyframe` | 勾选的集，每切一张 | 出场角色的锚点，按出场顺序，最多 3 张（Qwen-Image 3.0 的上限） | 先说明每张参考图是谁，再接切的 `frame`，最后是 frame.md 的收尾句 |
| `video:segment` | 勾选的集，每段一个 | 这一段各切的关键帧，按 Picture 顺序挂成 `reference_image` | 分镜的 `h3Prompt`；时长取 max(4, Σ切秒)，上限 15；画幅取分镜的 |

关于依赖和计划还有几点：

- 依赖也可以是以前确认单已经入库的那一张。勾了视频却没有关键帧（这张确认单没勾、以前也没生成过），计划时就报错。
- 场景图、道具图本阶段没有来源（backlog #28）。关键帧想挂但挂不上的参考，记在计划输入的 `unavailable` 里。
- 计划可以重复执行：同一张确认单里，同一个「节点 + 标签」只建一次任务。

## 任务状态

```
planned → submitting → submitted → running → succeeded → collected
             │                                  ↘ failed / rejected
             └ 崩溃后对账 → submitted / failed / unknown
planned → cancelled
```

- **submitting**：已经落库，请求在路上或者结果未知。它只能等对账，永远不回到 planned。回到 planned 就会被再提交一次，而两家都没有幂等键，那就是重复付费。
- **rejected**：内容审核没通过。
- **unknown**：对账对出多个可能，交给人处理。
- 每次转移都写一条 `task_event`。事件里不放凭据，也不放图片的 base64。

## 提交纪律：防止重复付费

1. 先写库，再请求。同一事务里把任务改成 `submitting`，记下进程号与时间，事务提交后才发请求。
2. 同一家供应商同一时刻只有一个提交在路上。这样崩溃后按时间窗对账才不会对错。
3. 提交不自动重试，按失败情况分别处理：

   | 失败情况 | 处理 |
   |---|---|
   | 网络错误、超时、408、5xx、响应看不懂 | 请求可能已经到达供应商，保持 `submitting`，等对账；这次运行不再往这家供应商提交，保证对账时间窗里只有它一个 |
   | 429 限流 | 确定没有创建任务，等一会儿再提交同一条 |
   | 审核没过 | 任务转 `rejected` |
   | 参数错、余额不足 | 任务转 `failed` |

4. 拿到供应商任务 id 立刻落库。唯一索引 `(provider, provider_task_id)` 兜底。
5. 另一个还活着的进程有「提交中」的任务时，`generate` 拒绝启动。

## 查询

- 查询请求可以重试。连续 3 次出错，这次运行先放下这个任务，它仍然算在途、占着并发数，汇总的 `pollGaveUp` 里会列出来。
- 供应商返回看不懂的状态（没有映射过的状态字、缺字段）时，按查询出错处理，**不改任务状态**。如果判成失败，任务就能被重新生成，而它可能还在计费。
- 供应商明确说查不到（百炼的 `UNKNOWN`）时，任务转 `unknown`，交给人到供应商控制台核对，不判失败。

## 恢复

`cli tasks resume`（`cli generate` 开头也会先做一遍）只处理进程已经不在的 `submitting` 任务。

- **对账方法**：到供应商任务列表里找，时间窗取提交时刻前 2 分钟到后 10 分钟，去掉库里已经记过的 id。
  - 唯一匹配：补记 id，转 `submitted`。
  - 没找到：转 `failed`，写明「提交没有到达供应商，可以安全重新生成」。
  - 多个匹配：转 `unknown`，列出候选 id，用 `tasks requery --provider-id` 指定是哪一个。
- **超出保留期**：供应商列表只保留有限时间，百炼 24 小时，MiniMax 7 天。超过保留期的，直接判 `unknown`。
- **百炼的列表是整个账号的**：同一账号下有别的程序在用同一个模型提交时，可能多匹配，结果就是 `unknown`，交给人处理。
- **任务列表取不全**（翻页到上限还没取完、请求出错）：不判「没到达」，任务保持 `submitting`，原因列在 `errors` 里，下次再对。
- **对账之后**：在途的继续查询；成功但没下载的重新下载。`planned` 不动，要提交新任务得由人发起 `generate`。

## 重新查询与重新生成

- **`tasks requery`**：只查询、下载，不花钱。成功但当时没下载下来的，再查一次能拿到新的结果地址；MiniMax 的地址有时效，7 天内都能重查。百炼的结果只保留 24 小时，超过就只能重新生成。
- **`tasks regenerate`**：新建一条任务，`attempt_of` 指向旧任务。下次跑 `generate` 时提交，计入预算。只有失败、被拒、取消、已入库的任务能重新生成；提交中、未知的不行，要先对账或重新查询。同一个「节点 + 标签」已经有一条没结束的任务时，也拒绝，免得两条一起提交。

## 下载

- 只下载 https 地址，跳转后也必须是 https；有超时。
- 先看 `content-length`，再边读边计数，超过 500 MB 就停，不会整个读进内存再判断。
- 只收图片和视频，并按类型给扩展名。临时文件不管成功失败都会删掉。
- 读参考图时，先确认文件路径在项目的素材目录里。

## 费用

一律按人民币记，换算用确认单里那份估算存的汇率，不读实时汇率。

- **预估**：每个任务按单价表估算。
  - 图片：输出张数 + 参考图张数。
  - 视频：秒数 + 超过 5 张的参考图。
- **实际**：按供应商返回的用量计算；用量缺失时按预估记。单价查不到时记 null，不猜。
- **失败与被拒**：
  - 百炼：不收费，记 0（官方说明）。
  - MiniMax：按量付费下失败是否收费，官方没写，记 null。
- **已花**：实际费用为空时，除了计划中、已取消的任务，一律按预估算。未知、失败的任务可能已经计费，宁可多算。
- **预算**：「已花 + 这一条预估」超过确认单的上限时，就不再提交。剩下的任务保持 `planned`，汇总里 `budgetStopped` 为 true。设了上限时，查不到单价、没法预估的任务不提交，会列在 `blocked` 里。

## 汇总与退出码

`generate` 输出每种状态的数量和以下字段：

| 字段 | 含义 |
|---|---|
| `blocked` | 依赖死了、没提交的任务，带原因 |
| `unknownSubmits` | 结果未知、停在提交中的任务 |
| `downloadFailed` | 生成成功但没下载下来的任务 |
| `budgetStopped` | 是否到了预算上限 |
| `pollGaveUp` | 连续查询出错、这次先放下的在途任务 |
| `problems` | 各任务最后一次出错的原因 |
| `spent` | 已花加在途预估，人民币 |

全部入库时退出码 0。有需要人看的情况时退出码 2，包括：被挡住、结果未知、没下载下来、放下了查询、到了上限、失败、被拒或未知。

地址配置（`endpoints.json`）只认两家的官方域名，因为 key 会随每个请求发出去。
